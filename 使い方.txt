MemoryHeatmap 1.2.2
アプリ別メモリ使用量・増減の監視ツール

■ 起動
MemoryHeatmap.exe をダブルクリックしてください。インストールは不要です。
Windows 11 x64、.NET 10 Desktop Runtime x64 が必要です。
.NET、ブラウザー、WebView2 は同梱していません。
通常権限で動作し、外部への通信や管理者権限の要求はありません。
2D の描画にはソフトウェアレンダリングを使用します。
Windows 11 22H2 の 2023 年 9 月更新以降のメモリ API を利用します。

■ ヒートマップ
四角の面積：アプリ専用の RAM 使用量（プライベートワーキングセット）。
同一の実行ファイルパスのプロセスを合算します。大文字・小文字は区別しません。
別パスの同名アプリは別の四角です。パスを取得できないものは PID ごとの表示です。
四角の色：10 秒以上前の直近サンプルとの差（通常 10～12 秒）。
赤は増加、緑は減少。1 MiB 未満の変化と比較準備中は暗い色です。
色の濃さは増減率に応じます。数値には 1 MiB 未満の差も表示します。
空き領域 OFF の面積は、表示中に取得できたアプリの専用 RAM 合計に対する割合です。
共有メモリ、OS などを含む PC 全体の使用量とは一致しません。

更新は 2 秒ごと。画面の初期配置は使用量順で、その後は既存アプリの並びを維持します。
新しいアプリは末尾に追加し、終了したアプリは次回更新で消えます。
毎回使用量順に並べ替える方式ではありません。変化を追いやすくするための仕様です。

■ 空き領域を表示
「ヒートマップ」の右にあるチェックを付けると、左端に現在の「利用可能 (空き)」を追加します。
空きは上下端に接する青灰色の長方形で、幅は利用可能量 ÷ 総物理メモリです。
上部の AVAILABLE と同じ値で、すぐ再利用できるスタンバイメモリも含みます。
右側は従来どおり、表示中のアプリの専用 RAM 比で配置します。
「その他の使用分」「検索対象外」などの領域は追加しません。
検索すると右側を検索結果のアプリで再計算します。1 件だけならそのアプリが右側を占めます。
空きの幅は検索に影響されません。検索結果なしでは右側は空白となり、空きは残ります。
アプリの面積は右側の中での相対比で、PC 全体に対する正確な容量比を示すものではありません。
空きの容量・総容量に対する割合はタイルとツールチップで確認できます。
空きは選択・右クリック操作・矢印キーによるアプリ選択の対象にはなりません。
一時停止中も切り替え可能です。追加の計測・タイマー・比較履歴のリセットはありません。
チェックを外すとアプリがマップ全体を使用します。総容量などが不正なときは計測待ちです。
上部の PC 全体の使用量の下に、表示中アプリの専用 RAM 合計と約 10 秒の比較であることを表示します。

■ 表示設定
初回は空き領域 OFF。変更時に EXE の隣の MemoryHeatmap.settings.json に保存します。
JSON の showWholeMemory は true / false です。次回起動時に選択を復元します。
設定も引き継ぐときは、EXE と一緒にこのファイルを移動してください。
ファイルなし・読込失敗時は OFF で開始します。読込失敗はチェックボックス付近に表示します。
保存に失敗すると「設定未保存」を表示します。現在の切り替えは有効です。
マウスを重ねると理由と保存先が分かります。別の場所への保存・権限昇格は行いません。
保存は一時ファイルからの置換で行い、終了時は保存完了を待ちます。

■ 操作
・四角・アプリ一覧・PID 行を右クリック：メモリ整理／タスク終了／ファイルの場所を開く。
・Shift+F10 またはメニューキー：フォーカス中のマップ・一覧・PID 行のメニューを開く。
・四角をクリック：右側で PID ごとの使用量と増減を確認。
・四角にマウスを重ねる：小さい四角もツールチップで詳細を確認。
・検索：アプリ名、PID、実行ファイルのパスで絞り込み。表示中アプリの面積を再計算します。空き領域 ON でも検索の動作は同じです。
・一時停止／再開：表示中の計測を停止／再開。再開時は増減の履歴を取り直します。
・右側のアプリ一覧：取得不可や使用量 0 のアプリも選択できます。
・狭いウィンドウでは、右側のパネルをスクロールできます。
・Ctrl+F：検索欄へ移動。検索欄で Esc：検索解除。
・Ctrl+Space：一時停止／再開。
・ヒートマップにフォーカスがある場合、矢印／Home／End でアプリを選択できます。

■ 値の意味
MiB = 1,048,576 バイト、GiB = 1,073,741,824 バイトです。
PC 全体の使用量は OS が報告する総物理メモリから利用可能量を差し引いた値です。
利用可能量には、すぐ再利用できるスタンバイメモリも含まれます。
総容量は OS が利用可能な物理メモリです。搭載 RAM の公称値と異なる場合があります。
コミット量は RAM 使用量とは異なり、ページファイルに退避した分も含みます。
各プロセスの行にマウスを重ねるとコミット量、共有分を含むワーキングセットを確認できます。

■ 取得不可・計測中
保護されたプロセスや別ユーザーのプロセスなどは通常権限で取得できない場合があります。
取得失敗を 0 として表示しません。「*」はグループの取得できた分だけの合計です。
グループに取得不可がある間は、そのグループの増減を計算しません。
起動直後、新規アプリ、再開直後は比較用の 10 秒分の履歴が必要です。
プロセスの起動時刻が取得できない場合は「比較不可」となります。
PC のスリープ復帰などで計測間隔が大きく空いた場合も履歴を取り直します。
PID と起動時刻で識別し、再利用された PID を別プロセスの履歴と比較しません。
アプリ単位の増減はプロセスの追加・終了も含む、アプリ全体の合計の差です。
一時停止中の表示値は停止時点のものです。

■ メモリ整理・タスク終了
四角やアプリ一覧からは所属 PID を選ぶ確認画面を開きます。対象は初期状態で未選択です。
PID 行からはその 1 件を選択済みで開きます。実行ボタンを押すまで操作しません。
「全選択」で一覧の操作可能な PID にまとめてチェックを付け、「解除」でチェックを外します。
操作前は「閉じる」で確認画面を閉じられます。実行中は「中止」、処理後は「閉じる」と表示します。
確認画面を開いた後に起動したプロセスや、子プロセスを自動で対象へ追加しません。
メモリ整理：選択したプロセスのワーキングセットを縮小し、専用 RAM の操作前後を表示します。
コミット量は解放されません。再アクセスで RAM 使用量が戻ったり、一時的に遅くなったりする場合があります。
CPU 使用中（1 コア換算で 10% 超）や前面の対象は整理をスキップします。
タスク終了：選択した PID を強制終了します。未保存のデータが失われる可能性があります。
システム・重要な処理、別ユーザー／サービス／別セッション、MemoryHeatmap 自身は操作できません。
起動時刻・パス・権限・生存状態が確認できない対象も操作せず、理由を表示します。
実行直前に PID・起動時刻・パスを再確認します。権限の昇格は行いません。
操作結果は確認画面に PID ごとに表示します。コミット量の前後は行のツールチップで確認できます。
実行済みの操作はマップ左上の黄色い小さな印と、右側の詳細・ツールチップに約 2 分表示します。
直近の操作記録は最大 32 件で、アプリ終了時に消えます。緑の減少には手動整理の影響も含まれます。
「中止」は次の処理を止めます。既に実行した整理や終了を取り消すことはできません。

■ 動作の範囲
整理・終了は明示的に選択した対象へ手動で行います。自動整理・自動常駐は行いません。
ウィンドウを閉じると計測も終了します。履歴はメモリ内に短時間だけ保持します。
タスクマネージャーとは集約方法、更新時刻、列の定義が異なるため数値は完全一致しません。

■ ソースからのビルド
.NET 10 SDK と Windows が必要です。外部 NuGet パッケージは使用しません。
PowerShell でソースのフォルダーを開き、次を実行してください。
  .\build.ps1
dist フォルダーに .NET 非同梱の単一 EXE が作成されます。
  .\verify.ps1
コア・実メモリ・隔離デスクトップでの WPF 操作／描画検証を行います。
通常のデスクトップを切り替える操作はしません。
描画倍率の検査は 96/120/144/192 DPI での画像出力です。OS の拡大率は変更しません。
