# MemoryHeatmap v1.0.1

アプリ自身のメモリ使用を最適化し、内部の構成を整理したプレビュー版です。
表示する値、2 秒の更新間隔、検索・一時停止などの操作は維持しています。

## 変更

- プロセス収集時の一時オブジェクトを減らし、実行ファイルの情報を再利用。
- 10 秒差に必要な情報だけを履歴に保持。
- 一覧行、色、文字の描画データを再利用し、変更した表示だけを更新。
- 収集ループ、履歴集約、一覧更新、描画の処理を分離。
- 自身の一時データが多くなったときだけ、間隔を空けてバックグラウンド GC を要求。

ワーキングセットのトリミングや他プロセスのメモリ変更は行いません。.NET 非同梱の単一 EXE です。

## 比較・検証

実 PC の 3 分間の監視で、専用 RAM 中央値が **90.8 → 64.6 MiB（約 29% 減）**、コミット量中央値が **113.7 → 88.1 MiB** になりました。
CPU は PC 全体を 100% として 0.071 → 0.076% でした。
収集処理の一時割り当て量は約 87%、固定 600 プロセスの集約処理では約 74% 減少しました。
同じ固定データを表示する検証では、専用 RAM 中央値が 80.0 → 45.8 MiB（約 43% 減）になりました。
実 PC の監視ではデータが変動するため、固定データとは結果が異なります。専用 RAM・コミット量・CPU の観測値と比較条件は [検証記録](https://github.com/mezon-web/MemoryHeatmap-Releases/blob/main/validation-v1.0.1.md) に記載しています。

旧集約処理との 240 フレームの一致、WPF・回収制御の 58 項目、実際の 128 MiB 確保・解放、1,500 アプリの表示を確認しました。
単独 EXE の起動・描画・正常終了、Chrome / Edge での説明書のオフライン操作も検査しました。
UI は隔離デスクトップ上の WPF イベント・状態検査、倍率は 100～200% 相当の画像出力 DPI による確認です。

## 起動・更新

**.NET 10 Desktop Runtime x64 が必要です。実行環境は同梱していません。**

Windows 11 x64 / 22H2 の 2023 年 9 月更新以降が対象です。
旧版を終了して、新しい ZIP を展開した `MemoryHeatmap.exe` を起動してください。
